### 说明

循环外
1、从磁盘中加载持久化定时任务作业到内存中
2、启动独立守护线程，每1s轮询一次磁盘中加载的所有定时任务，如果匹配上时间，则将该任务移除并加入一个等待执行的定时任务list
3、启动守护线程，每0.2s读取一次内存中的等待执行的定时任务list，如果有则去完成任务，与主agent loop 互斥
4、用户输入问题 
5、从实际情况获取上下文；获取工具；获取精简记忆目录，组装prompt
6、根据最近对话，调用llm拿到相关记忆索引
Agent Loop 循环体
LLM调用前
1、组装prompt，包含工具身份、tools、当前工作目录、技能、记忆，加载mcp
2、保存压缩前上下文快照
————————————————————————————————————
3、上下文3级压缩
1. L3级压缩，最后一条tool_result 如果超过一定长度就落盘，返回落盘地址
2. L1，掐头去尾，保留开头3条数据和末尾47条数据，中间数据替换成占位符。（注意：tool_use和tool_result 需成对）
3. L2，旧工具调用结果替换成占位符，只保留最近KEEP_RENCENT条数据，其他进入循环，如果长度超过了120就替换成占位符
4、应急处理压缩：如果上下文总长度超过一定范围，触发L4级压缩，调用llm总结上下文内容，用总结后的内容替换上下文

为什么是L3-》L1-》L2 ：
先用 L3 把"大块"变成"小引用"（低风险高收益），再用 L1 把"中间段"整条砍掉（粗粒度、不可逆），最后用 L2 把"剩下的旧内容"降级成占位符（细粒度、可逆）。反过来做的话，要么浪费 L2 的工作，要么破坏 tool_use/tool_result 配对，要么让"最近 N 条"的语义失真。
——————————————————————————————————————
5、定义了一个计数器，如果无操作了3次，注入提醒更新todolist
6、注入定时器任务list
7、根据记忆索引，加载磁盘内相关记忆，push到上下文最后一条
————————————————————————————————————————————
LLM调用
1、调用LLM
错误返回数据判断
1、如果有常规 瞬态错误，【429限流】：延时重试，【529过载】：切换模型，没有则继续延时重试
2、检查是否API错误提示上下文太长，太长则启动L5级压缩，总结消息，并保留最近5条上下文，直接进行下一次loop（continue）
3、判断是否是最大token使用超出上限，如果是则升级唯一一次的最大token，升级后重试仍然不行则退出循环
正确数据返回判断
1、将llm返回消息追加进message内
2、如果返回结果没用调用任何工具 response != tool_use说明已经给出最终答案，退出循环。将记忆快照写入新的记忆，调用llm整理记忆
3、累加无操作计数器
遍历llm返回结果
4、如果不是tool_use 则读取下一条返回结果
5、如果LLM调用结果为compact压缩，则执行L4级压缩，结束当前回合，进行下一次agent loop 【引用1】
6、判断工具的调用是否可以在后台进行，如果可以，启动守护线程在后台进行工具调用，生成一个随机bg_id用于维护工具调用结果和bg_id的对应表，将bg_id放入上下文中。如果可以直接调用，则直接调用工具，把工具调用结果放入上下文中
7、调用工具之后，将无操作计数器置为0
8、如果【引用1】没有进行压缩，搜集所有已完成的后台任务，将返回结果push进上下文中
9、更新prompt
其他内容
1、技能加载：扫描所有skills目录，构建技能注册表，并生成prompt提示词
